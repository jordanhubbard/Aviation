## Engineering issue tracking

GitHub Issues and pull requests in `jordanhubbard/Aviation` are the sole authority
for engineering work, dependencies, review, evidence and closure. Use `gh issue`
and `gh pr` with `--repo jordanhubbard/Aviation`. Do not create tasks in a separate
tracker or invoke retired task-lifecycle commands. This project is not opted into
MAC task runners; optional inherited runner skills do not change its tracker.

For substantive work, create or reuse a GitHub issue before implementation, keep
its acceptance checklist and evidence current, reference it from the PR, and close
it only when its completion evidence is admitted. This project-specific rule
supersedes inherited instructions to maintain local work checkboxes with `litai
work record` or `litai work close`. `docs/roadmap/active-work.md` is a reference
index; design documents and migration archives are not competing task ledgers.

See [the tracking guide](docs/development/issue-tracking.md). Preserve historical
IDs, snapshots and audit records; they are not instructions to contact a retired
tracker.
